# R1-09 Join ERN

Planned by the `planner` agent and built as planned.

## What was built
- **`/join`, "Become a member"**, as in the mockup:
  - **The form:** first and last name, e-mail address, university or organisation, country, city (optional), "I am a" (the six career stages), research interests (optional), Discord name (optional), and the box "I have read the Code of Conduct and the privacy policy".
  - **The side boxes** "Before you apply" and "What happens next".
  - All labels, help texts and error messages are from the mockup.
- **Errors:** they appear under their fields, with "Please check the marked fields." above the form. The entered values stay, but the agreement box must be ticked again.
- **Applications are their own table** (`membership_applications`), separate from members. They hold:
  - name, e-mail address, institution, country, city, career stage, interests and Discord name
  - the time of the agreement, set by the server
  - the status "open"

  No internet address and no browser data are stored.
- **After sending:** the confirmation of the mockup ("Thank you, Ada. Your application is received", the three steps, "No e-mail from us?"). No approval time is promised anywhere.
- **The e-mail "Your application to the Esports Research Network"** (HTML and plain text) goes to the applicant only, after the page has answered. It holds:
  - a copy of the details
  - how the board proceeds
  - how to have the application deleted if someone else applied with the address
- **Nobody can find out who is a member.** An address that already belongs to a member (approved or not) or to an open application gets the same confirmation. In that case nothing is stored and no e-mail is sent. The same holds when the hidden robot field is filled.
- **Protection against spam,** without any outside service:
  - a hidden field that people never see but robots fill
  - a limit of five sends per hour from one internet address, and three per day for one e-mail address. Every send counts, duplicates included.

  Beyond the limit, a "Too many tries" page appears.
- **Form pieces:** fields can now be marked as required (`*`) or optional, and there is a select box in the same style.

## How to see it
`php artisan migrate:fresh --seed`, `php artisan serve`, then http://localhost:8000/join. The e-mail is written to `storage/logs/laravel.log`.

## What was tested (30 new tests)
- **The page:** its wording and links, for a guest and for a member.
- **A valid application:**
  - stored with the server's time
  - the address in lower case
  - nothing set from outside (status, time)
  - the e-mail sent to the applicant
  - no user created
- **The confirmation:** its wording, no time promise, and the form again on reload.
- **Wrong input:**
  - every required field, with the mockup's message
  - a wrong e-mail address, an unknown career stage, an unticked box, and a value that is too long
  - the optional fields may be empty
  - after an error, the values are kept and the fields are marked for screen readers
- **No membership check through the form:** a taken address (approved member, unapproved user, open application, other capitals) gets a byte-identical page, nothing is stored and no e-mail is sent.
- **Spam:**
  - a filled robot field stores nothing and gives a byte-identical page
  - the robot field is hidden from people
  - both limits work, also across different internet addresses, and invalid sends count too
- A failing e-mail still gives the confirmation, and the application is kept.
- **The e-mail:**
  - it has an HTML and a text version, with the copy of the details
  - HTML in a name is escaped
  - it holds no link, no token and no time promise
- **By hand, with JavaScript off:** the errors, and the confirmation after sending. The page has no sideways scrolling at 375 pixels.

## What was not tested
- **Real e-mail delivery.**
- **Capitals in existing member addresses:** matching them without regard to capitals relies on MySQL. Members created through the platform are stored in lower case.
- **Behind the hosting's proxy:** whether the limit per internet address works there. If the hosting hides the visitor's address, everyone would share one limit. Check on staging.

## Good to know (for R1-10)
- Open applications keep their personal data until the board decides. Deleting the personal data of declined applications after 30 days is R1-10.
- Members have no "city" field. When R1-10 turns an application into a member, it has to decide what happens to the city.
- **No notice to the board:** the board gets no e-mail about a new application yet. The admin list comes with R1-10.
