# R0-07 Test data

## What was built
- **One test user per role** (`database/seeders/TestUserSeeder.php`). Each one is called "Test" plus the role name and has the address `<role>@example.test`:
  - `member@example.test`
  - `reviewer@example.test`
  - `final_editor@example.test`
  - `conference_team@example.test`
  - `database_lead@example.test`
  - `lecture_team@example.test`
  - `editor@example.test`
  - `admin@example.test`

  Every test user also holds the member role.
- **Twenty invented members** (`database/seeders/MemberSeeder.php`) across 20 countries and all six career stages:
  - The first eight are the example people of the mockup, with the roles the mockup's rights editor gives them. Maja Lindqvist is admin. Lukas Brandt is conference team and final editor. Amara Okafor is Database Lead and reviewer. Aiko Tanabe is reviewer.
  - Two more are given the editor and lecture team roles.
  - Five members chose not to be listed in the directory.
  - Addresses follow the pattern `first.last@example.test`.
- Every institution ends with "(example)".
- **The password** of all test users comes from `SEED_PASSWORD` in the local `.env`. `.env.example` sets `ern-local-test`. The server template has no such value, and the seeders refuse to run without one.
- **The seeders run only on a developer's computer and in the tests.** They refuse on staging and live, even with `--force`, so that test accounts with the public password from `.env.example` can never appear on a server. R0-11 creates the first staging admin with its own step, not with these seeders.
- Running the seeders twice changes nothing.
- The test factory from R0-05 and R0-06 stays as it is, for the automated tests.

## How to see it
```
php artisan migrate:fresh --seed
php artisan serve
```
Sign in at http://localhost:8000/members/sign-in, for example as `admin@example.test` or `maja.lindqvist@example.test` with the password `ern-local-test`.

## What was tested
- The seeders run on an empty database and make 28 users.
- **Test users:**
  - There is one test user per role, approved, holding that role and the member role.
  - A Database Lead passes the database gate. A plain member does not get into the admin area.
  - A test user signs in with the local password.
- **The twenty members:** they start with the mockup's people and roles, and have at least 10 countries, at least 5 career stages, and some members not listed.
- **For every user:** the institution ends with "(example)", the address ends with `@example.test`, and the career stage is one of the six.
- Running twice creates no duplicates.
- **Refusals:**
  - in production, through `db:seed --force`
  - on staging
  - a single seeder in production
  - without a local password

## Good to know
- The mockup's career stages "Postdoc" and "Lecturer" became "Researcher with a PhD", and "Industry partner" became "Practitioner in industry", the choices of the application form.
- Two people hold the final editor role in the test data: the test user and Lukas Brandt (as in the mockup). The rule "one person holds this role" is enforced later, in the rights editor (R1-15).
