# R1-21 Release notes and check sheet

## What was built
- `docs/checks/release-1.md`: twenty tasks for the release check on staging (R1-22). There are eight for a visitor, four for an applicant, four for a member and four for an admin. Each task says what to do, what should happen, and which mockup page to compare with. A short "Before you start" names what the tester needs, and which links are expected to answer "Page not found" for now (see the list in the sheet).
- The release notes for release 1 are the change log lines from R1-01 to R1-20 in `docs/CHANGELOG.md`.

## How to see it
Open `docs/checks/release-1.md` on GitHub.

## What was tested
- Each expected result was checked against the code and the templates: button labels, messages and page headings use the exact words of the site.
- The sheet has exactly twenty tasks.

## What was not tested
- Nobody has worked through the sheet yet. That happens in R1-22 on staging.
- The sheet assumes that the test admin on staging exists and also holds the Member role. That admin is created in R0-11, which is not built yet. R0-11's task text now says so.
- Staging must be able to send e-mail. Tasks 10, 12, 13, 15, 17 and 18 need real e-mail, and the tester needs two addresses of their own.
- The seeders do not run on staging, so the sheet only relies on content that the tester creates, or that is copied over by the content seeder.
- The mockup addresses (`#news` and so on) were checked against the mockup's source, but not opened at the published link.

## Review
The first review found six places where a tester would have reported "Broken" because the sheet was wrong:
- opening the welcome link a second time while still signed in
- repeating the applicant tasks with the same address
- an invented application that does not exist on staging
- an empty member directory
- notices that do not exist yet
- overview lines that appear only when there is something

It also found eight labels or steps that did not match the site. A second review found one wrong count (two applications wait at task 17, not one) and a mailbox the test admin may not have. All were corrected. Points 1 and 2 of the review (access, safety of data) had no findings in either round.
