# R0-08 Admin frame

## What was built
- **`/admin`**, with the mockup's header ("Admin area", "Signed in as …", "Board and admins only", "Back to the member area") and the tab bar: Overview, Members, Conference, Database, Teaching, Content, and the new System tab for admins.
- **Each tab is its own address** (`/admin/members` and so on) and checks its own rights on the server:

  | Tab | Who may open it |
  |---|---|
  | Overview | everyone with a role beyond member |
  | Members | admin |
  | Conference | conference team, reviewers, final editor, admin |
  | Database | Database Lead, admin |
  | Teaching | lecture team, admin |
  | Content | editor, admin |
  | System | admin |

  The tab bar shows only the tabs a person may open. The pages are empty for now: "This part of the admin area is being built."
- **The System page** shows the application version, the environment name, and the time of the last scheduled run in UTC. The version reads "development" until the upload workflow (R0-10) sets `APP_VERSION`.
- **The heartbeat:** the scheduled command `ern:heartbeat` runs every minute and stores the time in the new table `system_values`. Once the hosting's cron entry runs the scheduler (R0-11), the System page proves it works.
- **The footer link "Admin area"** appears only for people with a role beyond member.

## How to see it
```
php artisan migrate:fresh --seed
php artisan ern:heartbeat
php artisan serve
```
Sign in as `admin@example.test` (password `ern-local-test`) and open http://localhost:8000/admin/system. Sign in as `editor@example.test` to see a smaller tab bar.

## What was tested (27 new tests)
- **Every tab:**
  - a member is refused
  - the fitting role gets in
  - a role that does not fit is refused, for example an editor on Database
  - a guest is sent to sign-in

  The Conference tab is tried with each of its three roles.
- **The tab bar:** an admin sees all tabs, an editor sees only Overview and Content, a reviewer sees Conference.
- **Marking and addresses:** the current tab is marked, and an unknown tab answers 404.
- **The System page:** it shows the version, the environment, "Not yet …" before the first run, and the time after a run.
- **The heartbeat:** the command stores the time, and it is scheduled every minute.
- **The footer link:** it is hidden for guests and members and shown for a reviewer.
- An unapproved admin is refused.
- **By hand:** the System page at 1280 and 375 pixels wide, with no sideways scrolling.

## What was not tested
- That the hosting's cron entry really runs the scheduler. That is R0-11.

## Good to know
- The mockup's tabs are buttons inside one page. Here each tab is a link to its own page, so every tab works without JavaScript and checks its rights on the server.
- The header's "Member area" button is highlighted while in the admin area, as in the mockup.
