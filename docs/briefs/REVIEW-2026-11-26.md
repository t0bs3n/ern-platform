# Full review before the hosting (26 November 2026)

Tobi asked for a proper review and check of everything built in releases 0 and 1, before he starts `docs/HUMAN_TODO.md`. Four separate reviews looked at:
- access and permissions
- personal data and web security
- readiness for the hosting and the documents
- correctness, wording and tests

In addition, every migration and every test was run on a real MySQL-type database (MariaDB 10.11), not only on SQLite.

## What was found and fixed

**Must fix (all fixed):**
- **Sign-in:** a "remember me" cookie could still be set by adding `?remember=1` to the sign-in address. Only the person signing in could do this, but it broke the rule that only the session cookie is set.
- **MySQL:** on MySQL or MariaDB servers with an older setting, the moment an applicant agreed to the Code of Conduct would have been overwritten at every approval or decline. This was reproduced and fixed with a migration. GitHub now also runs every test on MySQL with that setting.
- **Text rule:** the call for abstracts named the person who is the Ombudsperson. A test now checks every public page.
- **Tests:** one test would have failed by itself in March 2027, because it relied on today's date.
- **Your to-do list:** in `docs/HUMAN_TODO.md`, R0-09 had gaps that would have stopped you halfway:
  - the site key that you cannot create yourself
  - the address of the site
  - the directory password, which would have vanished at the first upload
  - the secrets for GitHub, which were asked for before their names existed
  - the main domain possibly exposing the settings file
  - the first admin, who could not be created on staging

  R0-09 is rewritten. The parts for Claude are written into R0-10 and R0-11 in `docs/BACKLOG.md`.

**Should fix (fixed):**
- **Cookies:** a second cookie (XSRF-TOKEN) was set on every page. Now only the session cookie is set, and the CSRF protection stays on.
- **Protective headers:** every page now sends them. Other sites cannot frame our pages, and signed links are not passed on to other sites.
- **Password reset:** "Forgot your password?" is now limited per internet address and per e-mail address, so nobody can fill a member's inbox.
- **Test data:** the loaders for invented applications, events and notices now refuse to run on staging and live, each on its own.
- **Spreadsheet export:** the guard against formulas now also catches leading spaces and full-width signs.
- **Calendar:**
  - An event with a start time but no end now stays in "Coming up" until its day is over. Before, it vanished the moment it started.
  - Dates across New Year show both years.
- **Small fixes:**
  - Two e-mails started with a lowercase "thank you".
  - A test that could never fail now checks properly.
- **Documents:**
  - `README.md` described the starting state. It now explains how to run the site on your own computer.
  - The template `.env.staging.example` explains each value.
  - The Composer packages have their reasons in `docs/DECISIONS.md`.

## Found sound
- **Permissions:** every page and action checks the role on the server, and each has a test that refuses a guest, a plain member and the wrong role.
- **Members' privacy:** nothing reveals who is a member: not sign-in, reset, join, e-mail change or the directory.
- **Input and output:** Markdown, every input and every output are escaped. The only raw SQL parts use fixed column names and bound values. CSRF is on every form. Uploads are private.
- **Logs and data:** logs hold no addresses. "Download my data" holds only the member's own data. The clean-up jobs are scheduled.
- **Content:** the site content loader adds only what is missing and never overwrites an edit.
- **Packages:** `composer audit` finds no known security weakness in any package.

## Decisions by Tobi (afterwards)
- **City:** kept. Members now keep the city from their application, can change it under "My details", and find it in "Download my data". Admins see it on the member's page. It never appears in the directory. Tested.
- **Spelling of the board's texts:** US spelling stays. Recorded in `docs/DECISIONS.md`.

## Ideas left out (for later tasks)
- **Sessions:** after a password reset, end the member's sessions on other devices.
- **Calendar feed:** include past entries, so that calendar apps do not delete them.
- **Data download:** include the admin log entries about the member.
- **Applications:** delete open applications after a fixed time.
- **Admin content lists:** split them into pages once they grow.

## Not checked
- Anything on the real hosting: the folder layout, the cron job, the directory password, Apache's handling of `.htaccess` files and the MySQL version. These are checked in R0-10 and R0-11.
- A real screen reader, and colour contrast.
