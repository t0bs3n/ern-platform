# R1-01 Pages and news in the database

## What was built
- **Pages**: a title, a fixed address (for example `code-of-conduct`) and the text in Markdown.
- **News posts**:
  - a title and an address made from the title, which stays the same when the title changes
  - an optional category
  - a summary for lists, the text in Markdown, and an optional image with a description
  - draft or published, with a date
- **Who sees a post:** the public sees it only once it is published and its date has come. Drafts and posts dated in the future stay hidden (`News::published()`).
- **The Content tab** (`/admin/content`, for editors and admins):
  - It lists all news posts (with their date or "Draft") and all pages.
  - It has buttons for "New post" and "New page", and an "Edit" link for each entry.
- **Editing:**
  - Every form has "Save" and "Preview". The preview shows the text as it will look, next to the form, and saves nothing.
  - Errors appear under their fields, as in the other forms.
- **Markdown** uses the framework's own converter. Raw HTML is shown as text, never run, and `javascript:` links are removed.
- **News images:**
  - Images go to private storage (JPG, PNG or WebP, at most 2 MB) and need a description.
  - They are served through `/news/{address}/image`. Editors always see the image. The public sees it once the post is public. For a draft, everyone else gets "not found".
  - An editor can replace or remove an image.
- **The content of the mockup** is in `database/seeders/content/`:
  - the ten news posts
  - the ERNC27 Call for Abstracts (converted from the mockup's HTML to Markdown, tables included)
  - the ERNC26 summary

  `ContentSeeder` loads them. Unlike the test users, it may run on staging and live (`php artisan db:seed --class=ContentSeeder`). It only adds what is missing and never overwrites an editor's changes.
- The admin area frame is now one shared layout (`resources/views/admin/layout.blade.php`), so the next tabs only add their own panel.

## How to see it
```
php artisan migrate:fresh --seed
php artisan serve
```
Sign in as `editor@example.test` (password `ern-local-test`) and open http://localhost:8000/admin/content. The public news pages come with R1-03.

## What was tested (37 new tests)
- **Access:** all nine content addresses (list, new, save, edit, change, for news and pages):
  - refused for a member and for a Database Lead, with nothing saved
  - a guest is sent to sign-in
  - an admin gets in
- **Editing a post:**
  - an editor creates a draft, changes it and publishes it
  - the address stays when the title changes
  - addresses stay unique
- **Visibility:** drafts and future posts are invisible to the public.
- **Preview:** it shows the rendered text and saves nothing.
- **Safety:** `<script>`, `<b>`, `<iframe>` and `javascript:` links are not rendered.
- **Required fields and wrong values** are refused.
- **Images:**
  - an image needs a description
  - only image files are accepted (a `.php` file is refused)
  - the image lies in private storage
  - a guest and a member get "not found" for a draft's image, and the editor gets it
  - after publishing, everyone gets it
  - removing an image deletes the file
- **Pages:**
  - an editor creates and changes a page
  - the address cannot be changed afterwards
  - wrong and duplicate addresses are refused
- **Content seeding:**
  - the content is seeded (10 news, 2 pages, tables kept)
  - seeding again does not overwrite edits
  - it runs on the live site
- **Further checks:**
  - a preview while editing saves nothing (news and pages)
  - previewed text does not carry over into the next form
  - images from other websites are refused and never shown
  - a scheduled post is labelled and its image hidden, also from a Database Lead
  - replacing an image deletes the old file
  - a kept image needs its description
  - the page error messages
- **By hand:** the content list, the news form and the preview at desktop width.

## What was not tested
- Phone width for the admin forms. That comes in the accessibility pass, R1-20.
- The preview does not show a newly chosen image. The image shows after saving.

## Good to know
- **Images from other websites** in the Markdown text (`![…](https://…)`) are refused when saving, and never shown even if one got in: they could track visitors. Images go through the image field instead.
- A published post with a future date shows as "Scheduled, <date>" in the Content tab.
- Public news images may be cached by browsers for one hour.
- Outside the task, but needed: seeding the test users had become slow (several seconds), because the password check ran for every user. The password is now hashed once per run (`database/seeders/Concerns/MakesTestUsers.php`).
- **The old news posts:** `data.json` has only the summary of each old post, so their text is the summary for now. Their full texts on the old site need to be copied over before the cutover. `news.json` keeps each post's old address for the redirects in R1-18.
- **The mockup's Content tab** also shows "Notices for members" and "Press sources". They belong to the member area (R1-14) and to release 6, so they are left out here.
- **The ERNC27 call text** is seeded as a page, so R1-06 can show it on the conference page.
- **News posts cannot be deleted yet.** A draft can stay a draft. Deleting needs a decision on who may do it.
