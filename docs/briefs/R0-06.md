# R0-06 Roles and permissions

Planned by the `planner` agent and built as planned.

## What was built
- **Eight roles**, as in `docs/DECISIONS.md`: member, reviewer, final_editor, conference_team, database_lead, lecture_team, editor, admin. They are fixed in code (`app/Enums/Role.php`), with the names and descriptions of the mockup's rights editor.
- **Roles per user** are kept in the table `user_roles`, one row per user and role. A user can hold several roles. The roles go when the user is deleted. No form can set a role by accident, because roles are not a field on the user.
- **Gates**, one per area, listed in `app/Auth/Permissions.php`:

  | Gate | Who passes |
  |---|---|
  | manage-members | admin |
  | manage-conference | conference team, admin |
  | review-submissions | reviewer, admin |
  | decide-submissions | final editor, admin |
  | manage-database | Database Lead, admin |
  | manage-teaching | lecture team, admin |
  | edit-content | editor, admin |
  | administer | admin |
  | open-admin-area | every role except member alone |

- **A user who is not approved holds no rights**, even with roles. This also covers an approval that is withdrawn while someone is signed in.
- **The admin area check:** the route group `admin` (signed in, and a role beyond member). R0-08 puts every `/admin` address in it and adds the tab's own gate on top.
- **Template helper:** the framework's own `@can('edit-content') … @endcan`.
- **A "No access" page (403)** in the site frame.
- The test factory makes every user a member. `User::factory()->withRoles(Role::Editor)` adds more roles.

## How to see it
There is no screen yet. The admin area comes with R0-08. The tests show the rules.

## What was tested (65 new tests, many generated from the table above)
- **Every gate:** each role that should pass does pass, admin passes, a member without the role gets 403, and a guest is sent to sign-in.
- **The full table:** for every role and every gate, the answer matches the table. For example, an editor does not pass the database.
- An approved admin loses every right once the approval is withdrawn.
- Several roles for one user.
- A role is not stored twice.
- Roles are deleted with the user.
- The names and descriptions match the mockup.
- **The admin area check:**
  - a guest is sent to sign-in
  - a member gets the "No access" page in the frame
  - each of the seven other roles gets in
  - an unapproved admin is refused

## What was not tested
- No real page uses the gates yet. That begins with R0-08.

## Good to know
- The member role is given by code, not by the migration. Users who already exist get no member row. R1-10 (approval) and R1-19 (import) must give every new member the member role. No gate checks the member role today.
- All gates must stay in `app/Auth/Permissions.php`. The tests cover exactly that list, and one test compares it with a table written out by hand.
