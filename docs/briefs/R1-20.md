# R1-20 Accessibility and phone pass

## What was done
- **Every page of releases 0 and 1 was checked in a browser** at phone width (360 pixels), with JavaScript switched on and off. This covers the public pages, the member pages and every admin page, signed in as an admin. Each page was checked for:
  - exactly one main heading (h1)
  - a page title
  - no sideways scrolling
  - a label on every field
  - a description on every image
  - no empty links or buttons
  - no repeated ids
  - no skipped heading levels

  No page had a problem.
- **Keyboard:** stepping through the start page, the join form, the sign-in page, the ERNC27 page and the events page with the Tab key shows a visible outline on every element. In the events list, the outline goes around the whole card. This is on purpose.
- **Errors tied to their fields.** Fields built with the shared parts (`x-field`, `x-textarea`, `x-select`) already tie their error and help text. Fields built by hand were checked one by one. Fixed:
  - Five groups of choices in the admin area: news status, notice status, person group, event kind and conference status. Their error now sits inside the group and is tied to it. Notice status and conference status showed no error at all before.
  - Member rights: the error about a refused role change now sits inside the roles group and is tied to it.
  - Conference key dates: an error about the whole list (more than twelve rows) was shown nowhere. It is now shown and tied to the group.
  - Event time zone: the help text is now tied to the field.
  - News image: an error on "Remove the image" is now shown and tied.

## How to see it
`php artisan migrate:fresh --seed`, `php artisan serve`, then open any page in a browser window made narrow, or step through a page with the Tab key.

## What was tested (10 new tests)
- Every public address answers, with exactly one h1, a page title and the page language. This covers the fixed pages, every published news post, and every conference with its tab. Also tested: the join page after sending, the welcome link (valid and broken), and "Page not found".
- Every page has its own title. The only pages that share one are the two tabs of a conference, and the two steps of "Set a new password".
- For each of the groups of choices, the rights and the key dates:
  - a wrong value shows the error, tied to its group
  - without an error, nothing is tied

## Checked only by reading the code or by the automatic browser run, for the human check
- **200% zoom:** a desktop window at 200% is as narrow as about 640 pixels. The 360-pixel run covers it, but a person should zoom one page in a real browser.
- **Reduced motion:** the stylesheet switches animations off when the device asks for less motion. This was not tried on a device.
- **Screen reader:** nothing was tried with a real screen reader. On "Set a new password", a wrong e-mail address is shown twice: once at the top with the link "Ask for a new link", and once under the field. A screen reader may read it twice. This was left as it is so that the wording stays as it is. Decide in the release check.
- **Colour contrast** was not measured. The colours come from the mockup.
- **Keyboard** was checked on five pages, not on every page. The admin forms were checked by reading the code only.

## Ideas left out
- One shared part for a group of choices (legend, options, error), so the six groups stop repeating the same markup.
